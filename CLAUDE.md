## Edit → Studio debug loop

1. Change `agent/` locally, then run `npm test`, `npm run validate`, `npm run audit` (and the skill's `validate_aiui_audit.py`; Final status=BLOCKED is expected because this machine has no signing authority).
2. `git commit` + `git push origin main`.
3. In Studio (`https://aiui.rokid.com`) the whole "new agent" button at the top left opens a dropdown → "GitHub import" → put `https://github.com/cnYui/DoubleRunner/tree/main/agent` in the address box (set the form value as a whole; do not try to clear it with keystrokes) → "confirm import". Re-importing the same URL updates in place.
4. The "..." at the end of the project row (`button.agent-actions-button`) → "upload to cloud" → the row switches to "synced". A mouse click on "..." does not open the menu in the in-app browser; `element.click()` does.
5. In the chat box type `/debug` first and wait for it to become a chip, then type the "simulate the glasses device running the current page pages/run/index" instruction and send. The "enter" button on the card is covered by the floating effect-preview window, so click it with `element.click()`; the card then reads "entered" and the page moves into the 480 x 352 effect preview.
6. The first log line, `run onLoad … build=<BUILD> … gyro=… sound=… vibrate=…`, says which build Studio is actually running and what the runtime offers; `diag …` appears every 5 seconds with the real firing counts of each timer.
7. **The in-app browser pane must be visible**: while it is hidden `requestAnimationFrame` never fires, GitHub import gets stuck at "unpacking the archive", and the effect preview stalls.

## Measured in Studio 1.1.0 (2026-09-11)

- Lifecycle: `onTargetChanged(undefined → _current)` → `onLoad` (`wx.getWindowInfo()` is the 448 x 150 chat card here) → `onShow`; after "enter" the canvas moves into the 480 x 352 effect preview and the target stays `_current`.
- Click → `GlobalHook` + `Enter` (the page acts exactly once); swipe forward / back → `GlobalHook` + `ArrowUp` / `ArrowDown`.
- **The web host has no IMU**: the `Gyroscope` / `Accelerometer` constructors exist, but `start()` immediately yields `error: Host capability gyroscope.start is not configured on Web host`. The page falls back to the demo signal by design (`DEMO_WHEN_UNAVAILABLE`), and the state chip carries `· DEMO`. Only the device (Android host) has real readings.
- `Sound` works: system log `Web audio playback started … from_user_interaction=false`, so the beat is audible. `AudioContext` does not exist (0.17 runtime) and `navigator.vibrate` does not exist — **AIUI has no vibration API**, so the beat can only be audible and visual.
- The canvas context comes from `wx.createCanvasContext('curve', this)` (`querySelector('#curve').getContext` does not work), and drawing must end with `flush()`.
- `localStorage` works (`storage=yes`).
- Timers: the host only pumps them while the page renders, so the metronome is also polled from the frame loop and the UI refresh; judge real behaviour from the `diag` log.

## Page state machine (`_phase`)

`idle` (ready, sensor preview curve) → click → `running` (steps, metronome) → click → `paused` → click to resume / swipe back → `finished` (saves the record, draws the whole-run cadence chart) → click → `idle`. `onHide` while running pauses automatically and stops the sensor, metronome, and timers; `onUnload` silently saves an unfinished run that has steps. Swiping forward / back in `idle` / `running` moves the target cadence by ±5 (120 to 220) and retunes the metronome live.
